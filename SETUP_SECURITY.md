# 🔐 Безопасность и хранение данных

## Что изменилось в этом обновлении

✅ **История чатов перенесена на сервер** — теперь работает на любом устройстве
✅ **AES-256-GCM шифрование** содержимого сообщений в Upstash Redis
✅ **HMAC-проверка Telegram initData** на каждом запросе с пользовательскими данными
✅ **GDPR-style удаление** — кнопка "Удалить все мои данные" в профиле
✅ **Минимизация логов** — содержимое сообщений не попадает в логи Vercel

## Архитектура хранения

```
┌─────────────────────────────────────────────────────┐
│  Telegram → Mini App                                │
│                                                     │
│  Каждый запрос:                                     │
│  initData (с HMAC от Telegram) ──────┐              │
│                                       ▼              │
│  ┌─────────────────────────────────────────┐        │
│  │  Vercel Serverless Functions            │        │
│  │                                         │        │
│  │  1. Проверка HMAC (lib/user-data.js)    │        │
│  │     ❌ невалид → 401 Unauthorized       │        │
│  │     ✓ валид → user.id известен         │        │
│  │                                         │        │
│  │  2. Шифрование AES-256-GCM              │        │
│  │     перед записью в БД                  │        │
│  │                                         │        │
│  │  3. Расшифровка только для своего user  │        │
│  └────────────────┬────────────────────────┘        │
│                   │                                  │
└───────────────────┼──────────────────────────────────┘
                    ▼
        ┌─────────────────────────┐
        │   Upstash Redis         │
        │                         │
        │   user:{id}     → JSON  │ (профиль — не sensitive)
        │   chat:{id}:doc → 🔒    │ (зашифровано)
        │   chat:{id}:law → 🔒    │ (зашифровано)
        │   chat:{id}:fin → 🔒    │ (зашифровано)
        │   stats:{id}    → JSON  │ (статистика)
        └─────────────────────────┘
```

## Что нужно сделать после деплоя

### Шаг 1: Сгенерировать ключ шифрования

⚠️ **Это критический шаг.** Без ENCRYPTION_KEY приложение не сможет шифровать/расшифровывать историю.

В терминале выполните:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

Получите 64-символьную строку типа:
```
a3f5b8d92e7c4a1b6f3d8e5c7a9b2d4f6e8a1c3b5d7f9e2a4c6b8d1e3f5a7c9b
```

**Скопируйте её.**

### Шаг 2: Добавить ENCRYPTION_KEY в Vercel

1. Vercel → ваш проект → Settings → Environment Variables
2. Add New:
   - **Key**: `ENCRYPTION_KEY`
   - **Value**: вставить 64-символьный hex из шага 1
   - Все 3 галочки (Production, Preview, Development)
3. Save

⚠️ **СОХРАНИТЕ КЛЮЧ В НАДЁЖНОЕ МЕСТО** (менеджер паролей). Если потеряете — потеряете доступ ко всей зашифрованной истории навсегда. Менять ключ нельзя (старые данные не расшифруются).

### Шаг 3: Залить код

```bash
git add . && git commit -m "encrypted server-side user data" && git push
```

Подождать деплой (2 мин).

### Шаг 4: Проверка

1. Открыть бота → Mini App
2. Открыть любого агента → задать вопрос → получить ответ
3. **Закрыть Mini App, открыть с другого устройства** (или вкладку браузера в Vercel прямо)
4. История должна быть та же — значит сервер работает

В Upstash Console → Browser → ваша БД → должны увидеть ключи:
- `user:123456` — профили (читаемые)
- `chat:123456:lawyer` — зашифрованные blob'ы (нечитаемая base64 строка) ✓

## Что осталось НЕ зашифрованным (по дизайну)

| Данные | Зашифрованы? | Почему |
|---|---|---|
| Telegram ID, имя, username | ❌ | Уже публичны в Telegram |
| Streak, health/finance score | ❌ | Не sensitive, нужны для индексации |
| История чатов (содержимое) | ✅ | Может содержать мед/юр/фин данные |
| Загруженные документы | ✅ (когда реализуем) | Sensitive |
| Аналитические события | ❌ | Только счётчики, без содержимого |

## Что НЕЛЬЗЯ делать

❌ **Не меняйте ENCRYPTION_KEY** после первого использования — потеряете доступ к зашифрованным данным
❌ **Не коммитьте .env.local в git** — там приватные ключи
❌ **Не логируйте содержимое сообщений** — даже для отладки

## Право на забвение

В приложении в Профиле — кнопка **"🗑 Удалить все мои данные"**. При нажатии:
- Профиль удаляется из Upstash
- Вся история чатов (по всем агентам) удаляется
- Streak/чек-ины удаляются
- Rate limit счётчики удаляются
- Пользователь "выходит" — попадает на онбординг
- Локальный localStorage очищается

Технически — POST `/api/user/delete` с `{"confirmation": "DELETE_MY_DATA"}` после проверки HMAC.

## Тонкости и ограничения

### initData протухает через 24 часа

Telegram WebApp `initData` валидно 24 часа после генерации. Если пользователь долго не закрывает Mini App, через сутки запросы начнут возвращать 401. UI ловит это и показывает "Сессия истекла, перезапустите приложение".

### Размер истории — 50 сообщений на агента

Чтобы не разрастаться, храним последние 50 сообщений на агента. При превышении — старые удаляются. Можно изменить в `lib/user-data.js`, константа `MAX_HISTORY`.

### Что делать при компрометации ключа

Если ENCRYPTION_KEY утёк (украли с компьютера, попал в git и т.п.):
1. **СРАЗУ** сгенерировать новый
2. Подменить в Vercel env vars
3. Все старые зашифрованные данные станут нечитаемыми → удалить:
   ```
   redis-cli --scan --pattern 'chat:*' | xargs redis-cli del
   ```
   (через Upstash Console → CLI)
4. Пользователи начнут с пустой истории. Это лучше чем продолжать со скомпрометированным ключом.
